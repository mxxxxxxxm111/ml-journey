# Журнал ошибок

Файл для повторения. Читать раз в неделю, пополнять после каждой новой ошибки.
Формат записи: что было не так, почему, какое правило из этого следует.

## Недели 1–4: Python, NumPy, pandas

| Ошибка | Почему | Правило |
|---|---|---|
| Виртуальное окружение: «удобный интерфейс с инструментами» | это изолированный набор пакетов проекта | один проект = одно окружение, зависимости в `requirements.txt` |
| Словарь: обращение «по ключу и по значению», «неизменяемый» | к словарю обращаются только по ключу, он изменяемый | ключи неизменяемые, значения любые |
| `raise` без `try/except` | `raise` только бросает ошибку, программа упадёт | ловить в месте вызова: `except ValueError` |
| `shape` суммы (3, 4) + (4,) = (3,) | broadcasting растягивает меньший массив на каждую строку | ответ (3, 4) |
| `mean()`, `sum()` без `axis` | считается по всему массиву, а не по столбцам | `axis=0` по каждому столбцу, `axis=1` по каждой строке |
| Broadcasting = «сложить два массива поэлементно» | это обычная поэлементная операция | broadcasting начинается, когда формы разные |
| Векторизация = «представление в виде вектора» | это операция над массивом целиком без цикла | цикл внутри C быстрее цикла Python |

## Недели 5–6: регрессия и градиентный спуск

| Ошибка | Почему | Правило |
|---|---|---|
| Регрессия = «линейная зависимость», классификация = «выдаёт число» | регрессия это тип задачи: предсказать число; классификация предсказывает класс | линейная регрессия лишь одна модель для регрессии |
| `cost` вернул вектор ошибок | функция потерь должна быть одним числом | сумма квадратов, делённая на `2m` |
| `grad_w = 0` скаляром | веса вектор | `np.zeros(n)` по числу признаков |
| Градиент = «метод векторизации» | градиент это вектор частных производных, указывает на рост | идём в обратную сторону: `w := w − α·grad` |
| Масштаб без `axis=0` (`X.mean()`) | среднее считается по всей таблице, а не по столбцам | `axis=0`, статистики по train |
| Масштаб нужен «для точности» | без масштаба поверхность потерь вытянута, спуск идёт зигзагами | один `α` для всех признаков, быстрая сходимость |

## Неделя 7: классификация и метрики

| Ошибка | Почему | Правило |
|---|---|---|
| `2/2+0` вместо `2/(2+0)` | приоритет операций | скобки в знаменателе |
| В знаменателе recall все объекты | recall считает долю найденных настоящих «1» | precision `TP/(TP+FP)`, recall `TP/(TP+FN)` |
| `fillna` без записи результата | метод возвращает новый столбец | `df['col'] = df['col'].fillna(...)` |
| `Sex` вместо `Sex_coding` в признаках | в модель идут только числовые столбцы | проверять `X.dtypes` и `X.shape` |
| Результат `roc_curve` целиком в `plot` | функция возвращает три массива | `fpr, tpr, _ = roc_curve(y, p)`, затем `plot(fpr, tpr)` |
| `roc_auc_score` по классам | нужны вероятности | `predict_proba[:, 1]` |
| Одинаковые названия в списке признаков | признаки дублируются | каждое название один раз, проверять `X.shape` |
| «Не пропустить» = высокий порог | наоборот | для высокого recall порог **ниже** |

## Неделя 8: обобщение, регуляризация, CV

| Ошибка | Почему | Правило |
|---|---|---|
| Bias и variance названы метриками и перепутаны | это виды ошибки модели | переобучение: высокий variance; недообучение: высокий bias |
| Переобучение = «accuracy на train близка к 1» | важен разрыв | смотреть разницу train и validation |
| Кросс-валидация = «обучение на всём датасете» | данные делятся на k частей | каждая часть по очереди проверочная, модель обучается на остальных, берём среднее и std |
| `alpha` и `C` перепутаны | это обратные величины | `alpha` больше: сильнее штраф; `C` меньше: сильнее штраф |
| Штраф «за ошибку» | штрафуются большие веса | L2 уменьшает веса, L1 зануляет часть |
| Медиана и масштаб по всей выборке | утечка из проверочной части | считать внутри `Pipeline` по train-части |
| Выбор `alpha` по тесту | тест перестаёт быть честным | гиперпараметры по CV, тест один раз в конце |
| `['test_score']` у `cross_val_score` | он возвращает массив | сразу `.mean()` и `.std()`; словарь у `cross_validate` |
| Минус перед `accuracy` | минус нужен только у метрик `neg_...` | `neg_root_mean_squared_error` берём с минусом |

## Недели 9–10: деревья, лес, бустинг

| Ошибка | Почему | Правило |
|---|---|---|
| Gini, энтропия, прирост названы без объяснения | не понят выбор вопроса | прирост = Gini родителя − взвешенный Gini потомков, берётся максимум |
| «Лес лучше, потому что дерево даёт одно значение» | причина в разнообразии деревьев | усреднение разных деревьев уменьшает разброс (variance) |
| `Classifier` вместо `Regressor` для цены | цена число | регрессия: `...Regressor` |
| `y` (доллары) вместо `y_log` | метрика соревнования на логарифме | учить на `log1p(SalePrice)`, цену возвращать через `expm1` |
| Второй пайплайн использует первый | копирование кода | проверять, что в `cross_validate` стоит нужный объект |
| `cross_validate` без estimator | пропущен первый аргумент | `cross_validate(model, X, y, cv=5, ...)` |
| `X` оказался списком названий | перезаписана переменная | `X.shape` перед обучением |
| Early stopping: «когда предсказания начали снижаться» | останавливаются по метрике на validation | брать число деревьев с лучшей validation-метрикой |
| RMSE на `log1p` = «базовая модель» | это метрика на логарифмической шкале | baseline отдельная простая модель; `log1p` нужен, чтобы ошибка была относительной |
| Максимум на 400 деревьях прочитан как 800 | невнимательно прочитан график | сверять числа с таблицей |

## Неделя 11: признаки и пайплайны

| Ошибка | Почему | Правило |
|---|---|---|
| Target encoding = «кодирование целевой переменной при пропуске» | это кодирование категории средним цели | риск: редкие категории дают значение, равное цене объекта; нужно сглаживание или фолды |
| Структурные пропуски перепутаны с target encoding | пропуск значит «нет гаража» | категории `'None'`, числа 0 |
| `MoSold` как порядковый | эффект месяца не монотонный и циклический | категория (one-hot), деревьям можно числом |
| `MSSubClass` не закодирован | число-категория | one-hot |
| `select_dtypes('int64', 'float64')` | второй аргумент это `exclude` | `select_dtypes(include='number')` |
| Новые признаки добавлены после `num_cols` | `ColumnTransformer` отбрасывает столбцы вне списков | сначала признаки, потом списки; смотреть `len(num_cols)`; метрика не изменилась вообще, значит изменение не дошло |
| `make_pipeline(X_train, ...)` | в пайплайн передаются шаги, не данные | `make_pipeline(StandardScaler(), Model())`, данные подаются в `fit` |
| `y` после удаления выбросов не пересчитан | у `X` и `y` разное число строк | фильтровать вместе, проверять `len(X) == len(y)` |
| Выбросы удалены из всей таблицы | тест трогать нельзя | выбросы убирают только из train |
| Вывод «признаки помогли» при разнице меньше std | это шум | сравнивать с std CV |

## Неделя 12: без учителя и PCA

| Ошибка | Почему | Правило |
|---|---|---|
| `KMeans.fit(X)` вместо `X_scaled` | масштабирование не дошло до модели | inertia в миллионах это признак, что масштаба нет |
| Масштаб и PCA на всех данных до разбиения | утечка статистики теста | `fit` только на train, внутри пайплайна |
| `fit(X_train)` без `y_train`, `score(X_test)` без `y_test` | модели с учителем нужны ответы | `fit(X, y)`, `score(X, y)` |
| `y` вместо `y_train` в CV | разное число строк | CV считается на `X_train` и `y_train` |
| График «накопленной доли» по `explained_variance_ratio_` | это доли по отдельности | `np.cumsum(...)` |
| Перепутаны подписи осей, нумерация с нуля | невнимательно | `xlabel` число компонент, `ylabel` доля, номера с 1 |
| Silhouette 0.2860 и 0.2849 считались разными | разница 0.001 это ничья | выбирать `k` по локтю и silhouette вместе |

## Общие правила, которые встречаются снова и снова

1. Все обучаемые преобразования только на train, внутри `Pipeline`.
2. Гиперпараметры по CV, тест один раз.
3. Разница меньше std CV это шум.
4. Метрика не изменилась после правки: правка не дошла до модели.
5. Сверять размеры: `shape`, `len(X) == len(y)`.
6. Перед `fillna` и фильтрацией помнить, что результат нужно записать.
